# A5 — RCA agent and governance gate (Sonnet)
Read also: `docs/handoffs/A1.md`. Own: `prahari/agent/`, `prahari/governance/`, `runbooks/`.
Develop against `fixtures/rca.json`; do not wait for A3.
Agent:
- `runbooks/`: ~15 markdown runbooks (fault type × node type): symptoms, checks, remediation action, risk level.
- Retrieval: TF-IDF + cosine over runbook chunks; returns top-k with scores.
- Tools: `sql_query` (SELECT only, table allow-list excludes ground-truth tables/columns, row limit, parsed and rejected otherwise), `get_rca`, `search_runbooks`, `propose_action` (action from a fixed enum: reroute_traffic, restart_node, rollback_config, dispatch_field_team, throttle_traffic, no_action).
- LLM adapter interface with three providers: `none` (deterministic template narrative, English and Hindi templates), `anthropic`, `openai_compatible` (base URL + key from env). The tool loop has a max-step limit. Default is `none` and must be complete.
- Output: narrative, cited runbook id, proposed action, list of evidence references used.
Governance: abstract `Check` class, one subclass per check, registry, thresholds in `governance/policy.yaml`.
G1 confidence threshold · G2 top-1/top-2 margin · G3 groundedness (every node id and number in the narrative exists in RCA evidence) · G4 action allow-list and blast radius (dependent node count) · G5 PII/secret redaction (emails, phones, IPs, keys) · G6 drift status not red · G7 model has a registered card · G8 output schema valid · G9 no duplicate action on the same node within N minutes · G10 severity ≥ major requires a human.
Decision rule: any fail → `blocked`; G10 or any warn → `needs_approval`; else `auto_approved`.
Tests: one passing and one failing case per check; SQL tool rejects `DROP`, `UPDATE`, multi-statements and ground-truth access; Hindi template renders.
