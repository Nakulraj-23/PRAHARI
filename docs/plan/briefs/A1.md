# A1 — Data simulator and feature pipeline (Sonnet)
Read also: `docs/handoffs/A0.md`. Own: `prahari/sim/`, `prahari/pipeline/`.
Build:
1. Topology generator (networkx): hierarchical core → agg → access → cell, ~120 nodes, some redundant links, 3 regions, 3 vendors. Also a second, different topology (seed 7, ~80 nodes) kept only for generalisation tests.
2. KPI simulator: 1-minute samples, daily seasonality, vendor-specific baselines, Gaussian noise.
3. Fault injector for the 5 fault types. A fault at a root node changes its KPIs and propagates to dependent nodes (BFS over the topology, attenuated with distance; redundant links reduce impact). Each affected node emits symptomatic alarms with delay jitter → alarm storm.
4. Realism, required: noise alarms (flapping, spurious) at ~20–30% of volume; 10% of symptomatic alarms dropped; the root node's own alarm missing in ~15% of incidents; ~10% overlapping incidents; `raw_text` in vendor-specific formats.
5. `python -m prahari.sim.generate --days 30` writes everything to the DB, ground truth in `incidents` and `label_*` only. Target ≥ 600 incidents.
6. Live mode used by the API: `inject(fault_type, node_id)`, `apply_action(action)` (recovers the network), `scenario("firmware_drift")` (shifts latency baseline +25% for one vendor).
7. Pipeline: `build_alarm_features(df)`, `build_node_window_features(start, end)` (per-node alarm counts by type, KPI deltas vs rolling baseline, z-scores, node-type one-hot), `build_incident_graphs()` → list of (X, A, y_root, y_fault). Vectorised pandas/NumPy.
8. `pipeline/quality.py`: null, range, duplicate, timestamp-monotonic and referential checks; fails loudly.
9. Time-based split: train / val / test by incident start time, written to `artifacts/splits.json`.
Tests: propagation follows the topology; determinism under a seed; no `label_` column in any feature frame.
Done when: `make seed` builds the DB in under 3 minutes and quality checks pass. Handoff must list incident counts per fault type and noise ratio.
