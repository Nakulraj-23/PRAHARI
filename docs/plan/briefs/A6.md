# A6 — Monitoring and optimisation (Sonnet)
Read also: handoffs A1, A2, A3. Own: `prahari/monitoring/`.
Drift:
- Reference statistics saved at training time (per-feature bin edges and proportions).
- PSI and two-sample KS implemented with NumPy (unit-tested against scipy and a hand-computed case). Prediction drift: distribution of validator probabilities and RCA confidence.
- `run_drift(window)` → report: per-feature PSI/KS, status green (<0.1) / amber (0.1–0.2) / red (>0.2), stored in `drift_reports`. Expose a function A4 can call.
- Verify: no drift on a fresh normal window; `firmware_drift` scenario turns red and names the latency features.
- `retrain.py`: retrain on recent data, compare with the current card, promote only if not worse (write the comparison).
Optimisation (`make bench`):
- RCA: PyTorch vs ONNX Runtime vs ONNX dynamic-quantised — p50/p95 latency over 500 runs, model size, accuracy change. Markdown table to `docs/bench.md`.
- Profile the feature pipeline; report the top hotspot and one concrete speed-up with before/after timing.
- `loadtest.py`: asyncio + httpx, N concurrent clients against `/v1/rca` and `/v1/alarms/validate`; p50/p95/p99 and throughput.
Report honest numbers even if quantisation does not help; explain why in `EXPERIMENTS.md`.
