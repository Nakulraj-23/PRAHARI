# A4 — Serving and integration (Sonnet)
Read also: handoffs A1, A2, A3, A5. Own: `prahari/serving/`.
Build the FastAPI app implementing every endpoint in CONTRACTS with the Pydantic schemas from `prahari/schemas.py`.
- Models loaded once at startup (lifespan); `/v1/models` serves cards.
- Incident detector: background task every 10 s on live data — validated alarms clustered in time and topology proximity → incident → RCA → agent proposal → governance → row in `actions`. All of it written to `predictions` and `audit_log`.
- Approve → `sim.apply_action`, status `executed`; reject → logged with note. `blocked` actions cannot be approved (409).
- Serving path never reads `label_*` or `incidents` ground truth (A1's table); detected incidents live in their own table — add it via the handoff if missing.
- Errors: typed error body, 422 on bad input, 503 if a model is missing. Request-id middleware, structured JSON logs, latency histogram per endpoint in `/metrics`. CORS for the web dev server.
- `make serve` starts it; Compose runs API + Postgres + web.
Tests (httpx TestClient): each endpoint against `fixtures/` shapes; inject → incident appears → approve → recovered; blocked action returns 409.
Done when: PLAN §7 steps 1–5 work through the API with `LLM_PROVIDER=none`.
