# A2 — Classical ML: anomaly detector and alarm validator (Sonnet)
Read also: `docs/handoffs/A1.md`. Own: `prahari/models/anomaly/`, `prahari/models/validator/`.
M1 anomaly: IsolationForest on per-node rolling KPI features. Baseline: 3-sigma rule on z-scores. Report PR-AUC and F1 on test against fault windows.
M2 alarm validator (is this alarm real or noise?): features only from information available at alarm time — type, severity, node type, KPI z-scores at ts, alarms on same node in last 10 min (flap count), alarms on graph neighbours in last 5 min. Baseline LogisticRegression, then HistGradientBoosting. Calibrate probabilities (isotonic) and report precision, recall, F1, PR-AUC, Brier score, plus a threshold chosen on validation to favour recall of true alarms (state the trade-off).
Both: follow the model interface in CONTRACTS, write model cards with baseline vs model metrics, use the splits in `artifacts/splits.json`, fixed seed.
Tests: train on a tiny sample runs in <20 s; predict is deterministic; feature builder never touches `label_*`.
Log anything that did not work in `docs/EXPERIMENTS.md`.
Done when: `python -m prahari.models.validator.train` and `...anomaly.train` produce artifacts and cards.
