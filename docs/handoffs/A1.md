# A1 handoff — simulator and feature pipeline

## What exists
- `prahari/sim/`: `topology.py` (networkx generator, `NetworkModel` array view; MAIN 120 nodes seed 42, ALT 80 nodes seed 7), `kpi.py`, `faults.py` (propagation, KPI effects, scheduling, symptomatic alarms), `alarms.py` (noise, vendor raw_text: Nexa/Orion/Zenith), `generate.py` (CLI), `live.py` (`LiveSimulator`: `inject`, `apply_action`, `scenario("firmware_drift")`, `tick`, `reset_scenarios`), `constants.py`.
- `prahari/pipeline/`: `store.py` (`load_kpi` -> (T,N,6) tensor, `load_alarms` label-free allow-list, `load_ground_truth_incidents` training-only), `features.py` (`build_alarm_features(df, net, kpi)`, `build_node_window_features(start, end, settings)`, `build_incident_graphs(settings, split, window_minutes=15, with_ids)`, `feature_names()`), `quality.py` (`run_quality_checks(engine)`, raises `DataQualityError`), `splits.py` (`make_splits`, `load_splits`).
- Tests: `tests/test_sim.py`, `tests/test_pipeline.py`. 32 pass in ~14 s (with A0's), ruff clean.

## How to run
`make seed` (30-day main DB `prahari.db` + 7-day alt DB `prahari_alt.db`, splits to `artifacts/splits.json`). Alt only: `python -m prahari.sim.generate --alt --days 7`. Node order everywhere = sorted node_id. Seed resets the whole DB (drop_all).

## Measured (seed 42, 30 days)
- `make seed`: 67 s total (main 57 s incl. checks; alt 8 s). 49 quality checks pass on both DBs.
- 694 incidents: congestion 187, fibre_cut 136, config_error 133, hardware_degradation 126, power_failure 112. Split 485/104/105 train/val/test (chronological).
- 6577 alarms, 5,184,000 KPI rows. Noise ratio 25.0% (flapping + spurious). True alarms/incident: median 5, mean 7.1, max 73.
- Root alarm missing in 13.4% of incidents; 10.2% of incidents start during an earlier one (19.5% intersect another).
- Timings: full KPI load 19 s; `build_incident_graphs` all 694 = 20 s; one node-window feature query 0.66 s; alarm features for 6577 alarms 0.13 s. Graph X is (120, 34), A (120,120).
- Alt DB (7 days): 155 incidents, 1879 alarms, 80 nodes.

## Known gaps
- Faults/alarm text are my own design, so any model accuracy is on synthetic data. Incident windows overlap at split boundaries (no embargo).
- Live `inject` writes 10 min of telemetry; open faults persist until `apply_action` on the root node (other targets recover nothing). State in `artifacts/sim_state.json`. Live writes are not wrapped in one transaction.
- Serving window query scans via node join; no ts index (see EXPERIMENTS.md).
