# A0 handoff — scaffold

## What exists
- `pyproject.toml` (py>=3.11; extras `dev` = pytest, ruff), `Makefile`, `Dockerfile`, `docker-compose.yml` (api, web, postgres), `.github/workflows/ci.yml`, `.gitignore`, `git init` done (no commits).
- `prahari/config.py` (Settings, env prefix PRAHARI_: seed, db_url, artifacts_dir, runbooks_dir, fixtures_dir, policy_path, llm_provider, confidence_threshold).
- `prahari/db.py`: all 9 CONTRACTS tables, indexes (kpi (node_id,ts), alarms ts), `init_db(settings)`, `get_engine`, `get_sessionmaker`. `kpi_samples` and `nodes` etc. use SQLAlchemy 2.0 mapped style.
- `prahari/schemas.py`: Pydantic models for every endpoint, plus RcaOutput and GovernanceReport per CONTRACTS.
- Empty packages (sim, pipeline, models/{anomaly,validator,rca}, agent, governance, serving, monitoring), `runbooks/`, `artifacts/`, `web/` placeholders.
- `fixtures/*.json`: 16 files (one per endpoint, plus `action_decision`, `incident_detail`), `metrics.txt` for /metrics.
- `docs/EXPERIMENTS.md` header.

## How to run
`make setup && make lint && make test`. seed/train/serve/web/bench print "not built yet", exit 0.

## Measured
- make setup: ~111 s. ruff: clean. pytest: 18 passed in 0.25 s (16 fixture validations, fixture-coverage check, DB init test).

## Known gaps / notes
- Torch was installed from default PyPI wheel (PyPI only; download.pytorch.org CPU index unreachable from the sandbox), so it is the larger build. CI/Docker can add `--extra-index-url https://download.pytorch.org/whl/cpu`.
- `kpi_samples` has a surrogate `id` PK (contract lists none) so the table has a PK.
- Fixture values (model hashes, metrics = 0.0) are illustrative placeholders, not measurements.
- Dockerfile CMD expects `prahari.serving.app:app` (A4 must provide it).
- No local git commit made.
