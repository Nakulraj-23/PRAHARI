# A6 handoff: monitoring and optimisation

## What exists
- `prahari/monitoring/`: `stats.py` (PSI, KS in NumPy), `drift.py` (`build_reference`, `run_drift`, `latest_report`), `retrain.py`, `bench.py`, `loadtest.py`. `from prahari.monitoring import run_drift`.
- `run_drift(window=None, settings=None, store=True) -> dict` matches `DriftReportOut` (window None = last 6 h; `(start, end)` or `{start, end}` also work). Stores a `drift_reports` row, sets `id`. Features: 6 KPIs, 15-min mean latency and loss, plus validator probability and RCA top-1 confidence (scored only with >= 100 values). `extra` has per-vendor latency PSI, KS statistics, notes.
- Reference: `artifacts/drift/reference.json` (built from train days, outputs from train+val). It is built on first call if missing (about 2 min, so run `python -m prahari.monitoring.drift build-reference` after training). Rebuild after any model retrain (the report notes a version mismatch).
- `retrain.py`: `python -m prahari.monitoring.retrain alarm_validator|anomaly_iforest|rca_gnn [--dry-run]` trains into a staging dir, compares card metrics, promotes only if none is worse by > 0.002, writes `docs/retrain/*.md`.
- `make bench` (Makefile) -> `docs/bench.md`. Load test: `python -m prahari.monitoring.loadtest --base-url URL` -> `docs/loadtest.md`. Tests: `tests/test_monitoring.py` (12 pass, ruff clean).

## Measured
- Drift on normal test-period windows: 6 h 42/43 green (1 amber, PSI 0.15, not investigated); 3 day 8/8 green; 1 day 11/12 green (amber from validator output PSI 0.116). `firmware_drift`: red, latency_ms PSI 0.44, latency_ms_ma15 0.49, vendor Nexa 4.99, all other features < 0.01. A 72 h window hides it (PSI 0.005).
- RCA forward pass, 500 runs, 1 thread: PyTorch p50 0.269 ms / p95 0.447; ONNX fp32 0.138 / 0.167; int8 0.123 / 0.154. Size 113 / 112 / 43 KB. Top-1 0.966, top-3 1.000, fault F1 0.957 for all three (88 test incidents). End-to-end `predict` p50 46 ms, mostly the DB query.
- Profile: top hotspot is the KPI query (`fetchall`, SQLAlchemy rows). A1's CROSS JOIN fix: 1078 ms -> 30 ms (36x) for a 75 min window; raw cursor 20 ms. 24 h window 751 -> 470 ms with the raw cursor.
- Load test (scratch copy of the DB, one uvicorn worker, 4 shared cores, 15 s per level): /v1/alarms/validate 15.3 req/s p50 56 ms p95 95 p99 285 at 1 client; 7.7 req/s p50 957 ms p95 1838 p99 2050 at 8; 7.3 req/s p50 3948 p95 6894 p99 8431 at 32. /v1/rca 0.7 req/s p50 892 ms p95 4327 at 1; 3.4 req/s p50 1935 p95 6256 at 8.

## Known gaps
- /v1/rca at 32 clients: all requests failed with HTTP 500 `database is locked` (SQLite writes from `predictions`/detector). A4 should look at it; throughput falls with more clients.
- Load numbers were taken on a copy of the DB with the machine shared with other agents, so treat them as rough. Retrain was run once, on the validator, dry-run (same metrics; deterministic). RCA and anomaly retrain paths are untested end to end. "Recent data" is whatever the DB holds, with the existing splits.
- Output-drift PSI on small windows is noisy, so it is advisory in practice. The drift reference comes from simulated data; thresholds 0.1/0.2 are the conventional ones, not tuned.
