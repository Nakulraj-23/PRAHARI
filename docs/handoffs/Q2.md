**Run:** `.venv/bin/python -m tests.models.audit.rca_data` (85 s, needed by the RCA live gate), then `rca_audit 10` (~4 min) and the others (1-3 min each).
**Reproduction:** all card metrics reproduce exactly (tolerance 1e-4). Thresholds were re-derived on val and match. Test is used only for reporting, and the baselines are fair (MLP has the same architecture and early stopping; the 3-sigma rule is also tuned on val).
**RCA, GNN vs MLP, 10 seeds (42-51), test n=88:** top-1 GNN 96.4% ±1.1, MLP 95.3% ±0.6. Paired diff +1.0 pt ±1.6 (7 wins, 2 ties, 1 loss; p≈0.07). Fault macro-F1: GNN 0.949, MLP 0.951. Alt topology (n=47): top-1 99.4% vs 98.1%; fault F1 0.939 vs 0.975.
**Plainly: message passing gives a small, consistent, not significant gain on root top-1 (about 1 incident in 88) and none on fault type.** Top-3 is 100% for both.
**RCA, shipped model:** by fault type, top-1 is fibre 92.3%, power 100%, congestion 100%, hw 91.7%, config 94.7%. The 3 test errors are 1, 4 and 5 hops off; the 4- and 5-hop errors each picked the root of a concurrent incident. Root alarm missing: 9/11. The 17 windows with a concurrent incident score 88.2%; the other 71 score 98.6%.
**RCA calibration (top-1 prob):** 62 windows ≥0.99 conf, 100% right. 19 at 0.95-0.99, 94.7% right. 4 at 0.5-0.8 (mean 0.71), 50% right, so slightly overconfident at the low end.
**RCA robustness (shipped / 10-seed GNN mean / MLP mean), top-1 on test:** clean 96.6 / 96.4 / 95.3; drop 30% of alarms 96.6 / 95.1 / 93.5; +50% noise alarms 96.6 / 96.3 / 95.1; both 94.3 / 92.5 / 90.3. Fault F1 degrades more: 0.957 to 0.908 (drop) and 0.906 (both). Alt with both: 97.9% shipped. Injected noise has no KPI blip, so this is optimistic.
**ONNX:** 135 graphs (two node counts), max abs diff 3.8e-6, argmax agrees on 135/135.

**Anomaly 0.346: both a labelling and a model problem.** Of 444 test positive (node, incident) pairs, 157 are KPI-silent (simulated effect <0.15). Also 145 of 432 KPI-visible nodes raised no alarm, so they count as negatives. Re-scored against simulator-visible labels, PR-AUC is 0.461 (3-sigma: 0.244) and F1 0.516. The bigger flaw is in the model: recall on visible node-minutes is 0.71 at 0-5 min after start, 0.81 at 5-15, 0.25 at 15-30 and 0.02 at 30-60. The 60-min rolling baseline absorbs the fault (hw_degradation recall 0.19).
**Anomaly fixes:** (A2) freeze or gate the baseline (exclude flagged minutes, or use a same-time-yesterday baseline); (A1/A2) label from simulated KPI effect, or mask silent nodes; report time-to-detect per incident.
**Validator 0.998: no leakage, but a simulator shortcut.** The counts are causal: they match a brute-force strictly-earlier recount, and excluding same-second ties gives the same 0.9981. However, test noise alarms never have a prior neighbour alarm (mean 0.000), and true alarms almost never repeat a type (0.002 vs 1.03). Ablation PR-AUC: no counts 0.9945, counts only 0.954, categoricals only 0.929.
**Validator, what to report:** PR-AUC on the true class is inflated by a 78% base rate. Report noise-class AP instead: 0.9675.
**Validator calibration and robustness:** the reliability table is good (624 alarms at 0.997 pred/0.997 obs; 142 at 0.035/0.035). Robustness, P/R: drop 30% 0.962/0.989; +50% noise 0.936/0.991; KPI z missing 0.982/0.836.
**Gaps:** n=88 is too small for significance. My noise injection is KPI-free. The live anomaly gate takes ~25 s. Fix for A1: `_window_features` crashes on an empty *filtered* alarm frame (object dtype in `bincount`).
